# G0–G6 工作流与权限边界

状态：用户已批准原样冻结的 `0.1.4-draft`；已授权 G1 第一批五类来源及必要样例核查。G1 尚未完成；最终数据使用范围及后续阶段需分别独立审计与人工批准。协议原文件内的 DRAFT 表述是批准对象的历史文本，实际批准状态见 `approval_log.jsonl` 和 `protocol_version_history.jsonl`；不得为修改状态而静默更改已批准内容。

| 关卡 | 责任交付 | 独立审计 | 人工决定 |
|---|---|---|---|
| G0 | 主 Agent 配置、协议、版本与待决清单 | 角色边界、协议可审计性、配置加载及遗漏检查；记录证据和未知项 | 用户已批准 0.1.4-draft 原始哈希；后续 UNKNOWN 不转为 PASS |
| G1 | Researcher 数据来源、许可、时间与 vintage 证据 | 审核逐序列可得性和数据质量 | 数据范围与使用条件 |
| G2 | Researcher 因子、标签、交易日历与预处理设计 | 逐起点可得性、标签成熟、窗口时间方向 | 因子、目标与映射 |
| G3 | Developer 模型、嵌套时间验证、测试隔离和实验计划；实现可运行自动检查及负向测试 | Pipeline、PCA、As-of Join、双截止时刻、边界、参数选择和检查实现 | 模型实验方案和开发验证执行范围 |
| G4 | Developer 冻结配置、数据、实验与独立测试方案 | 正式回测准入前实际运行并通过全部适用自动检查与负向测试；独立审计冻结、测试及测试集使用历史 | 正式回测、测试范围与次数；FAIL/UNKNOWN 不放行 |
| G5 | Developer 结果及完整实验记录 | 结果和复现证据审计；保留负结果 | 批准结果使用；最终模型选择只使用获准的开发验证信息，最终测试集不得用于选模 |
| G6 | 重大变更或最终预测请求及影响分析 | 对受影响关卡重新审计 | 变更和最终预测各自批准 |

所有关卡必查项逐项采用 PASS、FAIL、UNKNOWN、NOT APPLICABLE。PASS 要有证据；FAIL 阻断整改并复审；UNKNOWN 阻断依赖步骤，人工可要求补证或批准明示受限探索，但不能将其改记 PASS；NOT APPLICABLE 须列理由和适用范围。没有报告、协议或相关批准时不得放行。阶段产物变化后原审计不自动适用。

所有输出记录任务 ID、时间、角色、阶段、协议版本和 SHA-256、文件路径和代码位置、输入快照/哈希、规则 ID、方法、证据、结果、局限及责任人。结果和不同意见分别保存；变更和复审追加记录并保留关联。无代码时明确写“未实现”。

每个文件必须有唯一写入负责人和交接记录。只读研究与冻结快照的检查可以并行；共享文件编辑及依赖阶段串行。Auditor 只读正式产物，可在隔离临时目录进行检查和报告，不得修改正式预测数据、模型或回测结果。共享沙箱不能硬性保证这一边界；须核对审计前后的快照哈希并人工复核，系统级隔离未建立前标为 UNKNOWN。

批准记录仅登记用户实际给出的决定、原始会话或文件证据、范围、时间、协议和产物版本、限制条件；不得伪造签字。`approval_log.jsonl` 登记了用户对原协议哈希的批准及第一批 G1 授权；不包含最终数据使用范围或模型执行批准。
